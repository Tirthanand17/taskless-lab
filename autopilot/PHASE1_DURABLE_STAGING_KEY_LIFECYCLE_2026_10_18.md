# FlowMinute Lab — Durable offline worker credential lifecycle

**18 October 2026 | Existing public Draft PR #5 | Test-only; no production connection**

The previous signed staging gateway verified an HMAC worker credential but persisted no revocation or rotation state. A previously signed request could be accepted after a new process started with the same key, even if a key should have been revoked.

New `autopilot/agent_staging_key_policy.py` implements explicit trusted-test-process **enroll, rotate, revoke** operations storing only a bounded, opaque **key ID**, original role, monotonic key generation, active/revoked status, and retired-key tombstones **inside the same SQLite database** as the one-transaction unified staging coordinator. It **does not persist raw HMAC credentials or key-derived fingerprints**, so tests generate new 32-byte credentials exclusively in memory. A revoked worker ID cannot be reactivated by an ordinary rotate/enroll. Rotated old IDs cannot be reused by a different worker.

The signed HMAC request now optionally includes the key ID, so it cannot be altered without invalidating the MAC. If a `StagingKeyPolicy` is supplied, the gateway requires a registered (role,key ID,key) triple and verifies its current, active, exact key/role **inside the coordinator's `BEGIN IMMEDIATE` task claim/complete transaction**, including any idempotent completion receipt replay. This establishes a meaningful **local atomic revocation boundary for cooperative gateway callers** rather than checking policy in a separate race-prone transaction. The previous non-policy two-element worker tuples continue to work as explicit test-only legacy fixtures; this is NOT an enforceable production default. Optional local `_authz_check` callbacks are used solely by the signed gateway; direct Python calls to the coordinator can still bypass policy.

Regressions cover enrollment and reopen, key rotation/old signature denial/new key acceptance, tombstone nonreuse, revocation denying even a previously committed completion-receipt replay, revocation after claim denying an uncompleted handoff, independent concurrent rotation-versus-claim serialization, rejecting malformed enrollment, and refusing to attach a key policy from another coordinator DB. Dedicated GitHub no-secret CI runs the suite.

The administrative methods themselves are **NOT remotely authenticated** and local actors with file permissions can still tamper with SQLite data. Key rotation is not full worker session cancellation, secret-manager lifecycle, trusted remote DB time or remote identity. This work does not create licensed natural voices, actual agent-produced videos, verified media/legal/fact rights, upload authorization, cloud deployment, an account/API connection, media persistence or billing.
