# FlowMinute Lab — offline signed admin command anti-replay rehearsal

**18 October 2026 | Existing public DRAFT PR #5, ₹0 recurring budget, no remote administration**

The previous offline `StagingKeyPolicy` stored worker enrollment, rotation, revocation and retired-key tombstones durably, but **the person/program invoking enroll/rotate/revoke was not authenticated**, and duplicate administrative commands had no persisted one-time nonce audit. An eventual remote administrative API must not accept an arbitrary caller's self-declared policy updates.

This change adds an **opt-in local signed admin gateway** (`autopilot/agent_staging_admin_gateway.py`) for bounded administrator-origin HMAC-SHA256 signed `enroll`, `rotate` and `revoke` actions only. An administrator ID maps to a separate 32-byte+ runtime-only secret, not to any ordinary stage worker key. The signature covers action, worker, role, current and new key IDs, opaque one-time nonce and expiry. A trusted-local gateway clock rejects an expired or >120-second-future request. Canonical SHA-256 of the signed action's actual fields is stored with administrator ID and action under the bounded non-secret `staging_admin_commands` ledger in the **SAME SQLite `BEGIN IMMEDIATE` transaction** as a successful key-policy mutation. Replay fails; a malformed, stale or unsuccessful request rolls back the nonce. Policy metadata, key-generation records and retired identifiers remain as before. Secrets are never stored in SQLite or source.

Eight new regression tests cover correct enroll→rotate→revoke and restart audit, wrong MAC / tampered scope / different key, expired and future requests plus disallowed `upload_video`, one-time nonce replays, failed rotate transaction rolling back the nonce, two independent competing SQLite admin calls leading to one mutation, corrupted local ledger denial, and proving that stored SQL audit rows contain no admin secret. Existing direct-key-policy tests still run.

**Strict nonclaims:** The older `StagingKeyPolicy.enroll/rotate/revoke` methods are STILL directly callable by trusted local Python code without a signed admin guard, by design for backward-compatible tests. This is **not a production remote administrative security boundary**, cloud-hosted service, independently trusted database time, externally authenticated administrator, deployed secret manager, or real worker termination. The HMAC secret is injected by a test harness; there is no production provisioning, rotation or recovery. There is no YouTube/Google account access, independent rights/narration approval, real media upload, billable provider, real D1, laptop access or public release. The original production release/nonce ledger remains unmodified and both PRs #4/#5 stay DRAFT/unmerged. Original **21 production acceptance subphases over six incomplete major phases remain open**. Infrastructure recurring cap ₹0/month.
