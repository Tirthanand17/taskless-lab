# Phase 3 — Signed acoustic-review sidecar byte binding (offline)

**19 October 2026 · Public Draft PR #5 · No actual acoustic observations**

The existing two-role detached Ed25519 reviewer claim included `evidence_sha256` but did **not open or validate** any file with that digest. Reviewers could therefore sign an arbitrary, syntactically valid hash without providing a document showing what was supposedly checked. The new *optional stricter verification path* `autopilot/cloud_acoustic_review_evidence.py` reads a previously existing **≤8 KiB** UTF-8 JSON sidecar for each signed reviewer, rejects nonregular/relative/symlink/missing/oversized files and file mutations during reading, validates a fixed schema with no duplicated fields, and compares the **actual SHA256 of the opened bytes** with each reviewer's Ed25519-signed `evidence_sha256` after the original role+signature verification.

The schema binds the original full decoded MP4 SHA, word-timestamp candidate digest, current authored SRT SHA, precise English/Hindi lane and episode, transcriber versus independent listener identity, untrusted claimed observation method, and three exact sampled word/timestamp references (first, middle and final word). No raw voice recording, OAuth token, private signing key, actual transcript (except 3 synthetic word anchors), media copy or network request is stored by the inspector. Any edited sidecar—even if re-signed to the same test key—must match the canonical reference words/times and cannot falsely set real-world independence or publishing flags.

**Trust boundary and unfinished wiring:** This strict intake is deliberately **separate and opt-in** from the earlier detached-signature verifier and SQLite transcript-review ledger, preserving their existing offline test interfaces. Consequently the existing ledger does **not yet require** sidecars; code must not report that the replay journal now authenticates their contents. A future exclusive production service must enforce strict intake before accepting any signed review, carry the actual evidence hashes into its journal and bind an independently controlled public-key registry. Passing sidecar inspection proves only file-byte integrity and metadata consistency. Fake reviewers can still fabricate a matching synthetic sidecar; this does NOT prove any human actually listened, an approved offline ASR ran, accurate Hindi/English words were spoken, subtitles aligned, or voice/visual licensing was granted.

10 no-secret synthetic tests create sidecar files only under ephemeral CI temporary directories, sign them with temporary Ed25519 keys and reject byte tamper, wrong time anchor even after a resign, wrong media/language/transcript, duplicated JSON keys, absent/symlink/oversized files, false rights flags and missing signed roles. The existing full Content Quality Gate automatically discovers this file. No real media generated or captured, no cloud/account connection, no YouTube/OAuth changes, no laptop access or charges.
