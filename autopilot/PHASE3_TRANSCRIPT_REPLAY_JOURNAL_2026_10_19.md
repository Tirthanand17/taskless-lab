# FlowMinute Lab — bounded signed transcript-review replay ledger (offline)

**19 October 2026 | Existing public Draft PR #5 | No external media/account activity**

The earlier `cloud_signed_transcript_reviews.py` verifies a transcriber and separate listener's detached Ed25519 signatures, hashes and short-lived decisions **but has no durable anti-replay record across process restarts**. A caller could repeatedly present a once-valid receipt or silently replace the accepted review of an episode if a future workflow stored only the latest packet.

New `autopilot/cloud_transcript_replay_ledger.py` provides **separate, offline-only SQLite append auditing**, not the preexisting Phase 4 YouTube publish/release nonce ledger. Its `OfflineTranscriptReviewLedger.commit()` verifies the existing signatures, current authored SRT and actual-claimed MP4/audio checks within **one `BEGIN IMMEDIATE` transaction**, then atomically records the two globally unique reviewer receipt IDs, canonical transcript SHA including every word/timestamp, original video SHA, episode, language lane, source-SRT hash, and a SHA256-linked immutable sequence. There is NO persisted private Ed25519 key, voice, raw speech, raw transcript, uploaded video or OAuth credential. Requests using consumed receipt IDs cannot be admitted twice, including after a restart or in a multi-client SQLite race. Every new review for the same episode requires the exact preceding audit-head hash; old/stale writers fail instead of replacing the latest record. **Any video SHA can be assigned at most once across the staging journal**, preventing one synthetic video from being reused to attest different languages.

Each write and status read rechecks the bounded audit chain (cap 4096), episode-head index, and consumed-receipt index. The status and transaction receipt always refuse claims that actual narrated speech, independent real-world reviewer identity or YouTube publishing are verified. A lost response is reconciled via a read-only current_status query; reusing the original signatures is not an idempotent mutation. We deliberately do not create a live DB, account connection, cloud replay store or a background agent.

11 no-network tests: durable restart/replay denial, compare-and-swap review supersession, concurrent racing clients admitting only once, rejection and transaction rollback, partial old-receipt reuse after a new video, corrupt audit chain detection, receipt-index corruption detection, bounded ledger cap, global media SHA reuse denial across Hindi/English episodes, and absence of private signing keys or publish approval. Tests use preexisting synthetic script and disposable Ed25519 keys, never real speech or a rights authority. They are discovered by the existing full Content Quality Gate (cryptography already installed), with no additional billed workflow.

**Scope limits:** SHA chains inside a writable SQLite file are not protected from an attacker who can rewrite the entire database; an independently held signed audit root and hardened cloud data boundary remain necessary. This ledger is not a production identity system, a mechanism for recurring monthly free compute/storage, a host-attested clock, transcript accuracy or a proof a human listened to voice.
