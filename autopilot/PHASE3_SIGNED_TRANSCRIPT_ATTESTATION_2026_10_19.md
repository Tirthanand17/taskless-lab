# Phase 3 — detached transcript attestations (signed records, not real speech validation)

**19 October 2026 · Existing public DRAFT PR #5 · No external enrollment or publication**

The original word-timestamp intake checked a user-supplied candidate against scripted Hindi/English draft subtitle cues and the prior hash-bound original MP4/AAC waveform, but the supplied text had no issuer/signature identity or replay freshness. This is a distinct trust boundary from the *already existing* signed media/rights review in `autopilot/signed_review_gate.py`, not a replacement or duplicate publication approval.

The new `autopilot/cloud_signed_transcript_reviews.py` expects a separately provided, **trusted** public-key registry (one transcriber and one independent listener, different reviewer IDs and active Ed25519 public keys). Signed claims bind every Unicode transcript word and word timestamp through canonical `transcript_sha256`, exact final MP4 SHA256, original draft-SRT SHA256, intended episode/language lane, signed reviewer role, decision ACCEPT/REJECT, bounded separate content-evidence digest, notes, receipt ID and short-lived issue/expiry times. The verifier checks the original transcript's structural rules first, key enrollment/role/expiry/signature, distinct reviewer IDs and receipt IDs, and excludes creator/publisher identities. Tampering, self-declared key substitution, revocation, cross-lane replay or negative verdict remain blocked. Nothing stores a secret/private key or triggers external services.

**Crucial limitations:** A synthetically generated Ed25519 signature proves only control of an ephemeral test key, not that a real independent reviewer listened to the actual narration or holds a license. Untrusted `evidence_sha256` still points to a caller-declared record, not an independently opened audio transcript. No backend can convert a matching synthetic word list into verified acoustic recognition by inspecting signatures alone. The two positive test-role signatures thus yield **SIGNED_TRANSCRIPT_RECORDS_AWAITING_REAL_WORLD_VERIFICATION**, never verified audio, spoken language, Hindi/English accent, distinct natural voices, subtitle word-level sync, asset rights, channel publishing or autonomous upload.

Ten deterministic no-network tests with freshly generated in-memory keys cover original Hindi/English 3-lane signing shapes, forgery, transcript/video/SRT hash changes, revocation/registry misbinding, reviewer exclusion, stale/future clock, explicit rejection/missing second role, duplicated replay ID/role, unsigned decision change/invalid evidence, and all flags remaining production blocked. They run in the existing Content Quality Gate, which already installs cryptography; this step does not add pip packages or new workflows/charges. All source tests and notes are in public DRAFT code; the actual recording and any private reviewer identity must remain outside public CI.
