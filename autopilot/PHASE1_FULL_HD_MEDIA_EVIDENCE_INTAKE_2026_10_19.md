# FlowMinute Lab — read-only full-HD artifact evidence intake

**19 Oct 2026 · Public DRAFT PR #5 · Offline-only media inspection, no publication**

The previous 30-day capacity admission depended entirely on caller-provided `FullLengthTrial` metadata, while the existing 1-second native-HD benchmarks cannot establish full 42-second or 432-second video capacity. This new adapter accepts **only an existing, ordinary full-length media file per English Short (42s), Hindi Short (42s) or Hindi long (432s)**, with fixed 1080×1920 or 1920×1080 H264/AAC at CFR 24fps. No video/audio is generated or saved by the intake.

`autopilot/cloud_full_media_evidence.py` computes SHA-256 and exact file size, runs fixed local FFprobe (`-count_frames`) to confirm exactly one full-length native-HD video stream AND one AAC audio stream, then uses FFmpeg to decode **all** video and audio, not just container headers. It checks byte checksum/size/inode a second time after inspection and refuses missing/relative/symlink/oversized/modified files. Subprocesses have bounded timeouts, no shell or network, exact fixed command arrays, and strictly limited probe output. Caller-entered render wall time and RAM **remain self-declared and are labelled unverified**. The resulting `TechnicalFullHDObservation` binds an exact file digest, frame count and technical result, but cannot assert natural speech, caption synchronization, third-party rights, reviewer identity or release consent.

`evaluate_observed_media_capacity()` translates any observed triplet into the existing 90-video monthly ₹0 admission model while **always setting narration/caption and rights reviewer approval to FALSE**. Such technical-only inputs therefore remain `NO_VERIFIED_ZERO_COST_CAPACITY`, even if all native video bytes and private provider quotas somehow fit. Provider allowance data still requires independent account-level verification and owner's separate consent. To close a real Phase 3/4 production acceptance later requires an independently authenticated reviewer and an approved storage/voice/render service; this module must not grant that authority itself.

Eight regression tests check mocked FFprobe/FFmpeg controls and before/after source bytes (mocks explicitly do NOT prove a real full-HD clip was created), wrong frames/resolution/codec/FPS/extra streams, decoder failures, symlink/resource bounds, refusing an actual **tiny one-second test clip** generated on the existing FFmpeg-enabled CI runner, preserving strict rights/narration vetoes, and rejecting falsely elevated technical status. CI runs under existing public Content Quality Gate and Cloud Scout workflows, with no new paid workflow, artifacts or full-length renders.

No Nirala/laptop, download, paid cloud, new service connection, private CI or media storage, channel OAuth, real YouTube upload/schedule/publish, or recurring charges. Both PR #4/#5 remain DRAFT/unmerged; ₹0 recurring monthly cap; **21 production acceptance subphases in six unfinished phases remain OPEN**.
