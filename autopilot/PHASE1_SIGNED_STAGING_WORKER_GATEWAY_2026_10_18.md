# FlowMinute Lab — Signed staging worker identity gateway

**18 October 2026 | Public Draft PR #5 | NO cloud deployment or real credentials**

The unified staging coordinator previously trusted a caller's supplied specialist `actor` label, not proof of possession of a particular worker's credential. This software-only proof adds `autopilot/agent_staging_auth_gateway.py` as an opt-in **test-local HMAC-SHA256 verified gateway** for staging `claim` and `complete` operations.

A trusted in-memory registration maps each bounded worker ID to an original department-specialist role and a **separate 32+ byte key**. The gateway authenticates a canonical signed request covering worker ID, action, video ID, exact task ID, expected task generation, expiry, lease duration, optional Handoff SHA and completion receipt ID. It derives the acting role from the verified registration, not a caller-supplied role. Claimed signatures live at most 120 seconds. Authenticated claims pass `expected_generation` to the unified coordinator's transaction, so a previously signed claim cannot be replayed once its generation changes. Typed completion also validates the exact canonical Handoff payload digest and reuses the existing durable, idempotent completion acknowledgement.

GitHub's no-secrets dedicated Agent CI now runs the nine new tests covering signed completion and lost-response retry across reopen, forged or swapped MAC/role/task/secret, wrong-role valid signature, expired/future/unsigned/unsupported upload requests, old-generation claim replay after retry, changed output, weak/reused keys, racing worker claims, and strict optimistic generation checks. Keys are generated at test runtime via `secrets.token_bytes(32)`, with **no static keys committed**.

**Limits:** Local Python callers can still invoke the coordinator directly and bypass the gateway. The injected service clock is not a remotely trusted database clock; worker enrollment, secure key storage/rotation, host isolation and actual multi-machine authentication are not implemented. This is NOT a deployed HTTP worker, Cloudflare service, OAuth action, production identity approval, human legal/fact/rights review, audio generation or permission to publish. All artifacts remain `UNVERIFIED_STAGING_ARTIFACT`. The real Phase 4E release/nonce ledger is unaffected. Both public PRs remain draft and unmerged; monthly recurring cloud budget stays **₹0**. No Nirala/laptop, private Actions, production D1, external account/service or charge was accessed. The tracked **21 production acceptance subphases across six incomplete major phases** remain open.
