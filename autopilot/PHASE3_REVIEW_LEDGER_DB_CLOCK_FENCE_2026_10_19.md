# FlowMinute Lab — local SQLite-time signature freshness in review audit

**19 October 2026 | Existing PUBLIC DRAFT PR #5 | No provider or publishing**

The previous review-ledger `commit(...now=...)` forwarded a timestamp directly from its caller to the detached Ed25519 signature verifier and hash-linked event's `accepted_at_utc`. An adversarial integration could backdate its verifier clock to accept expired signed reviews or move it forward to deceive audit chronology. This flaw affected ONLY the local offline signed transcript review rehearsal, not a deployed service (none exists).

The ledger now queries `CAST(strftime('%s','now') AS INTEGER)` from **local SQLite inside its existing `BEGIN IMMEDIATE` transaction**, validates all current signatures using that time, and writes an event time from the same local clock. Optional caller `now` is at most a five-second sanity check; it **can never select the verification timestamp** and a wildly stale, fake future or timezone-naive timestamp is rejected before signature admission. Previous committed review events are audited for UTC-aware nondecreasing timestamps and new admissions fail if the local SQLite host clock is earlier than the last accepted event. Existing consumed receipt anti-replay, media/text hashes, CAS supersession, tamper checks and signed key-scoped reviewer roles continue unchanged. The new report explicitly marks `local_sqlite_time_checked_in_transaction=true` and `remotely_trusted_database_time=false`.

Four new no-secret regressions use **freshly re-signed synthetic Ed25519 records against the disposable runner's actual clock**, not the unrelated fixed-time signature verifier fixtures: caller backdating/future-date/naive-date refusal, persisted event time equal to the SQLite-chosen second, a simulated local clock rollback after journal reopen rejecting a second revision, and far-future SQLite host time refusing already expired attestations even when `now=None`. All run in the existing Content Quality Gate (no new workflow).

**Limits:** SQLite gets time from the SAME machine's OS wall clock. This is NOT protected against an OS root administrator changing host time **before the first event** or rewriting the entire SQLite DB, nor does it create an externally attested trusted time authority, independent review IDs, actual narrated audio, synchronized captions or a hosted cloud worker. The test uses synthetic signs and candidate words, not genuine speech. No user laptop/Nirala, new external service/credentials, private CI, production DB, Google OAuth or uploads/charges.
