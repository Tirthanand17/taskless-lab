# FlowMinute Lab — strict signed staging command protocol and local SQLite host clock

**19 October 2026 | Public Draft PR #5 | No external deployment**

New `autopilot/agent_staging_command_boundary.py` limits the optional local staging command facade to THREE exact JSON commands: **signed worker.claim**, **signed worker.complete**, and **signed admin.apply** (enroll/rotate/revoke only). Inputs must be ≤8 KiB with exactly matching typed keys; duplicate JSON fields, unsupported actions, altered signatures, fake task IDs, malformed or oversized evidence arrays, non-finite JSON values, generic Python/SQL/file/secret commands and upload/publishing are denied.

The optional `SQLiteHostClock` reads `strftime('%s','now')` from the local SQLite host. Under this new mode the worker coordinator obtains mutation timestamps **inside its existing `BEGIN IMMEDIATE` SQLite transaction**; the worker/admin gateways also recheck signed expiry in the same transaction before mutations or receipt replay. Existing explicit deterministic timestamp test fixtures remain unchanged. Existing HMAC-worker identity, nonsecret durable key revocation, signed admin one-time nonce ledger, exact parent SHA evidence, three-active-video/four-task admission and receipt idempotency carry through untouched.

The new no-secrets tests exercise end-to-end admin enrollment → worker claim → evidence-bound completion → post-restart identical receipt replay, duplicate/out-of-schema JSON rejection, expired and far-future signatures, rotation invalidating a signed worker command, admin nonce replay, two competing SQLite clients, and unpublishable status. Dedicated agent CI and full quality CI exercise this prototype.

**Caveat:** SQLite time here is still the machine's local OS wall clock, not independently attested remotely trusted database time. This in-process class does NOT provide an isolated deployment, protected database ACLs or authenticated HTTP endpoint: a local Python module can directly invoke the existing coordinator or policy. A future production service requires exclusive key/DB ownership, authenticated remote ingress, TLS/network isolation, real worker lifecycle cancellation and trusted remote DB time, subject to explicit owner approval. No live D1/OAuth/YouTube services, paid tools, user laptop, real voices/media, render or publishing are accessed.
