Your Power Automate flow reports success. Every box is green. The script ran without throwing an error. But the Excel report still shows yesterday's numbers. How is that possible? And can Power Query actually refresh itself in the cloud? Today we'll build a small realistic demo, trace the exact limitation Microsoft documents, and compare three practical ways to keep reporting data current. I'll also show when a simple folder import is better than a complicated automation. These are fictional example records, not a real company's data.

Imagine a small sales operation. Three regions send CSV files each day. Yesterday, the combined Excel report had twelve orders worth eighteen thousand four hundred dollars. This morning a new file arrives with an extra four orders worth six thousand two hundred. The source folder changed. A Power Automate flow runs a script that calls workbook dot refresh all data connections. The flow tile turns green. Yet the worksheet still has twelve rows and the old total. The flow ran, but the intended refresh did not happen. That is a different thing from an upload failure or a bad SUM formula.

The crucial detail is the execution environment. Microsoft says Office Scripts run by Power Automate use independent Excel sessions. In a Power Automate cloud flow, most refresh operations are not supported. Workbook dot refresh all data connections refreshes only when the source is Power BI. When the source is another Power Query connection, the call can return successfully while doing nothing. The same documentation says several PivotTable refresh methods return successfully but do nothing in flows. So the green check on the flow can be completely genuine, while the report data is still stale. Don't mistake the completion status of a script for proof that a data source refreshed.

How do we fix this? First, separate what kind of refresh you actually need. If someone opens the workbook in Excel Desktop before using it, a refresh on open may be enough. Microsoft documents a setting under Data, Queries and Connections, the connection's Properties, and the Usage tab. You can choose Refresh data when opening the file. For supported connections, you can also configure a refresh interval in minutes while Excel is running. Those are Excel application behaviors. They are not a promise that a closed workbook in SharePoint will update itself overnight with no active Excel session. For a local team report, though, that simple setup may be all you need.

Second, if the real requirement is an unattended cloud report, consider moving the refresh into a system that actually supports scheduled data refresh, such as the appropriate Power BI semantic model or dataflow. The precise options depend on your workspace, gateway, credentials and licensing. A Power BI dataflow has scheduled refresh settings; a cloud reporting architecture can separate ingestion, transformation, and dashboard refresh. The point is not to sell everybody a Power BI license. It is to stop depending on an unsupported Excel cloud-script refresh behavior when your report must update while nobody is at a desk.

Third, you may not need to refresh an Excel Power Query at all. If your real goal is simply to append newly received records into a master table, an upstream flow can collect the files or rows through supported connectors and write them to a target data store. That is a different architecture from running a refresh command. It needs its own checks: duplicates, missing files, permissions, schema drift, and what happens when a flow retries. A robust automation doesn't just turn green. It proves that the intended records arrived.

Now let's make the source data itself easier. When files share the same column names and types, Excel Power Query can combine them from a folder. In Excel Desktop, choose Data, Get Data, From File, From Folder. Select a dedicated folder containing only the CSV files you want. Choose Combine and Transform Data, check the sample, and review the applied steps. Three region files become a single table with a consistent schema. Add a fourth matching file, refresh the query, and the new rows appear. Microsoft's documentation says the columns do not need to be in the same order, but the column headers, data types and number of columns should be consistent. Avoid unrelated files and stray subfolders. You should also inspect failed files rather than blindly skipping errors.

This distinction matters: From Folder is an excellent repeatable transformation, but adding a new file does not automatically make the workbook refresh in the cloud. It still requires an actual refresh mechanism in a supported environment. The combination step and the scheduler are two different problems. Treat them separately.

Before you trust any automation, verify three pieces of evidence. First, did the source change? Use a source timestamp or expected file count. Second, did the refresh actually execute in a supported environment? Check connection status and any refresh history, not only the flow badge. Third, did the output change? Compare row counts, last order ID, and a control total. For our fictional example, the target should have sixteen orders and twenty-four thousand six hundred dollars. If the workbook still shows twelve orders and eighteen thousand four hundred, it is stale, even when the flow says success.

So the final rule is simple. Use Excel's refresh-on-open when a person opens the workbook. Use supported scheduled cloud data refresh when the report must update unattended. Use direct ingestion when the goal is to move new records, and use Power Query From Folder when you need repeatable combination and cleaning. Pick the system that meets the actual requirement, and prove freshness with data, not with a green success badge.
