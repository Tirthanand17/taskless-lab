# Branch 1 — replace the static Chrome Notifications pilot with a real Find-in-log exercise

**Scope:** original real browser footage on temporary GitHub Actions runner. Still **REVIEW ONLY, NO YOUTUBE**.

## Why change the actual lesson rather than game a pixel score?

The last independent decoded final-video audit [#43847139330](https://github.com/Tirthanand17/taskless-lab/actions/runs/43847139330) rejected the shortened 22.604-second notifications demo: **84.1% near-static genuine application pixels**, **3.5s** longest freeze, and no source-app visual change within three seconds. Changing a Chrome permission default moves just a few pixels; repeated navigation is distracting. The previous 33s demo also failed at 81.5% near-static. No proof of better viewer retention exists.

Rather than relaxing the existing 45% internal editorial motion screen, painting fake UI, or moving a fake cursor, we changed the pilot's subject to an action that naturally *has* a visibly useful result: **real Chrome's built-in Find feature** on a clearly labeled original fictional diagnostic log. Chrome's own help documents Find and Ctrl+F at https://support.google.com/chrome/answer/95440 and Find-next Ctrl+G at https://support.google.com/chrome/answer/157179.

## Authentic source and creative design

- Creates a real local HTML document with exactly **780 clearly fictional log lines** and **12 spaced ERROR entries** on the ephemeral runner. The original file's SHA-256 is bound into the closed application receipt; real Chrome opens the actual `file:///` fixture.
- Chrome opens the actual native browser Find bar and jumps to an ERROR before recording starts. The opening proof is the real found matching word, never an invented browser screenshot.
- Three 8-second recorded chapters: next-match jumps through the log, a purposeful visual comparison with scrolling manually, and Ctrl+F / Ctrl+G finding more error lines. Actual scroll positions and unique areas are verified; if genuine browser Find fails, the capture must fail closed. No external websites or account data.
- Original 22-second editorial brief and three Kokoro narration chapters describe the local fictional data explicitly, with a better-fit phone crop of actual browser pixels.
- Retains original Calc five-chapter capture unchanged, original audio and media hash checks, independent physical pixel QA threshold unchanged, and owner approval=false.
