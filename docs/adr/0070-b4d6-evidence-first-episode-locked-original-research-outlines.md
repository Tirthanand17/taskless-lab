# ADR-0070 — B4d6 evidence-first source selection and one-source-per-episode creative research outlines

**Date:** 2026-11-06, IST. **Track:** Branch 2, GitHub-hosted unattended daily research. All YouTube publication, external AI provider, paid cloud, final factual/rights approval and owner-channel authentication remain **disabled**.

## Verified before-change gap

Trusted main [run 42220078702](https://github.com/Tirthanand17/taskless-lab/actions/runs/42220078702), after merged PR #79, collected **2/3 actual source article pages**, one RSS entry fallback, and retained two mutually aligned research receipts (artifact 13502643498). However the chosen three episode research stories contained **only 1 directly fetched article**, because `daily_editorial_board.build_editorial_board` prioritized **new subject family and publisher before evidence tier** on the second/third selection. A headline-only source can thus displace a directly fetched public article even though the article bytes have been observed.

Also, the existing dormant optional `script_draft_agent.build_draft_input(slot, observations)` builds a context from *all* articles in the day's six-record source batch without checking that any individual source matches the episode's research lead. This risks attaching an irrelevant source citation to a proposed video when model access is eventually owner-approved.

## Implemented source-ranked daily creative research

1. The editorial selector first considers **directly observed article bytes**, then verifiably observed RSS entries, then headline-only ideas. It still rejects near-duplicate article titles, repeated source URLs and exact subject hashes across supplied prior-day history. For the **long video** it chooses a first-party publisher's directly observed page when available (OpenAI / Google DeepMind vendor-owned host, or an arXiv first-party-hosted author preprint), over a direct secondary news publisher when both are observed; direct secondary pages still beat first-party **unread** RSS entries. Short AM and PM retain distinct unverified source subjects, publisher diversity as a secondary criterion and different visual/story angles. First-party **does not mean true, peer-reviewed, independent, accurate, or licensed**.
2. New `autopilot/source_locked_script_briefs.py` **physically builds three original non-factual research storyboard outlines** on the trusted daily GitHub runner: four research/visual beats per Short and nine for the long. It generates source-specific research questions and original **synthetic/reproducible** visual directions for agents, models, data, cybersecurity or developer tools. These are starting tasks for later human/source-grounded editorial drafting, **not final narration** and not asserted current news facts.
3. Each source-linked outline is independently bound to the B4d5 exact **reconciled original three-slot plan**, B4d2 recalculated board and B4d3 signed-by-code (NOT signed by owner) source observation hash. Only if that **exact selected original article** was really fetched will it produce a **single-source optional model proposal input** through the existing `script_draft_agent.build_draft_input` validator. It checks the source ID, publisher, title, content digest and observed type; an RSS-only or headline-only article gets **no source-backed model context**. Every model permission flag remains false; zero calls. This helps avoid accidental story-to-source cross-contamination if a private owner-approved script model is connected later.
4. On every trusted GitHub daily run the detailed outline/lead/input JSON exists **only ephemerally** under the hosted runner's `out/`. It is validated, used to report numeric counts, and **deleted** after use. The usual GitHub artifact remains exactly **two sanitized public receipts** without headlines, URL queries, copyrighted source bodies, PDF figures, narration, media or secrets.
5. Adversarial offline tests cover **2 observed/1 RSS**, **1 secondary observed/2 primary RSS**, all-article, all-unobserved and no-topic days, source swapping, fake model/media approvals, digest mutation, exactly 1 observed source per eligible episode, schema/scene count and safe CLI/no overwrite.

## Important limitations

- **Only the observation count proves a page was fetched**. Neither the URL nor SHA256 proves semantic truth, expert fact review, independent corroboration, copyright or usage rights. An arXiv author abstract could be an unreviewed preprint. A vendor article can be biased. An external third-party article may contain errors or copyrighted creative material.
- **Original "research storyboard outlines" are not scripts**. No actual generated narrative voice, 60-second Shorts, new long footage, or fresh November videos are created by this milestone. Do not claim the previously successful static science-v7 demonstrations prove novel independent daily content.
- The optional model context is still **headline-level descriptive metadata**, not full article text or verified claims. It is **NOT sent to any provider**. Private-owner consent, approved provider data use, budget, source-level claims verification and full creative/watch review remain hard requirements before provider calls or YouTube publishing.
- The channel's independent seven-day unattended proof still requires **21 real published videos**, owner-channel readback, rights+fact review, a secret-managed cloud, scheduling and valid authenticated YouTube OAuth. Baseline about **40/100 readiness, 0/21 actual verified releases**.

## Live acceptance

An exact-head PR test run must pass dedicated GitHub Daily Foundation adversarial tests, repo-wide Content Quality, Cloud Scout and actual Remotion/FFmpeg audio/video smoke. The **trusted main** run must report **2 or more episode source-locked direct article research contexts when 2 distinct articles are observed**, 3 original storyboard research outline structures, no external model call and no YouTube writes, plus exactly two aligned sanitized receipts. If sources fail or are near duplicates, do not invent a quota.
