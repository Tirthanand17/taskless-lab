## Official AWS S3 references checked 2026-11-04

1. [S3 Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html): protection is for an individual object VERSION. Compliance mode retention prevents even root from deleting a protected version or shortening retention before expiry. This may have irreversible legal and storage-cost consequences.
2. [Configuring Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-configure.html): Object Lock requires versioning, and disabling it later is constrained. **DO NOT enable Object Lock or create any real bucket without owner-approved retention and cost terms.**
3. [S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html): If-None-Match star prevents overwriting an existing CURRENT object. In a versioned bucket with a current delete marker, the same key may be created again; neither condition nor a content-addressed path proves eternal one-use. 412/409 conflicts are possible.
4. [PutObject checksum and retention](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html): provide a SHA256 checksum with individual Object Lock setting. Read back the actual immutable version, never infer SHA from an ETag.
5. [GetObject specific version](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html), [object lock readback](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html): verify exact VersionId, full returned SHA256, body length, ObjectLockMode and RetainUntilDate through version-specific HeadObject/GetObject.
6. [S3 SSE-KMS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html): specify a narrowly scoped customer KMS key and independently verify actual IAM/key policies, encryption and account. Metadata is not encrypted solely by SSE-KMS.

## Implemented transport and integrity policy

- Original source story and claim-surface docket are regenerated independently at both plan and physical write preflight. Exact 43/127/43 source-linked original files (MP4, original WAV, captions, original thumbnail, scene proofs and motion frames, FFconcat) must be present with correct bytes; extra, symlink, missing, altered or renamed files fail. Source, narration, title, thumbnail and all 210 literal visible/spoken surfaces share their original SHA root. Producer's technical report is not real human/owner proof.
- Strict proposed storage intent: exact bucket, region, specific customer KMS key ARN, logical object prefix and selected 1–30 day retention. This intent dataclass NEVER authenticates the real owner, IAM, cloud resources, charge acceptance or legal retention terms.
- For each exact object, use one SDK PutObject request with IfNoneMatch star, explicitly supplied base64 SHA256 checksum, SSE-KMS and exact KMS ARN, per-version ObjectLockMode COMPLIANCE and ObjectLockRetainUntilDate. Object user metadata contains only episode name, original source docket SHA and asset SHA, not confidential source text.
- S3 boto3 SDK must have retries total_max_attempts = 1. Never automatically retry a potentially successful write after timeout, ambiguous failure, lost version ID, 412/409 error, or checksum/readback mismatch. Stop and require an independent operator audit. No deletes, rollback or archive cleanup API exists in this adapter.
- The upload response MUST include a non-null VersionId. Read back precisely that version using independent HeadObject/GetObject, verify returned full bytes and size, SHA, expected KMS key, actual ObjectLock mode/date and source metadata. Even a successful upload with missing readback is still UNCERTAIN and has no release authority.
- Only after ALL original objects pass version-specific readback, write a canonical UNAPPROVED final manifest containing the original source-script/claim-media hash and every original object key/version/SHA, then independently read back its own immutable version too. This is NOT an atomic multi-object transaction, cross-job durability, permanent independent anchor, version deletion prohibition or backup guarantee. Retained orphan versions may exist if a partial run fails.
- Every result says real cloud IAM/owner identity, real review, rights, immutable cross-provider audit, full human playback, backup, and YouTube release are FALSE. A technically staged package is not fact-checked or publishable.
