## Owner-scoped read-only inspection API

`autopilot/owner_private_network_image_preflight.py` exposes three independently invocable Python functions: `verify_private_network`, `verify_signed_owner_image`, and `safe_read_only_gate`.

Their caller (a future separately approved protected owner worker) must supply:

- Actual **pre-existing** EC2 and ECR read-only SDK clients; no public-PR or default credential discovery in this module.
- Explicit pinned AWS account, Region, nondefault VPC, **two different private AZ subnets**, task security group, distinct VPC interface endpoint security group, same-account private ECR repository, immutable image **sha256 digest**, and exact 40-character source commit. **No defaults** selecting a billable account, service, region or cloud spend.
- Owner-enrolled Ed25519 public key and its out-of-band pinned **SHA-256 fingerprint**, source-to-digest signed JSON and exact signature. No private signing key is accepted or generated by production code. Hosted tests only use disposable fake keys.
- Explicit timezone-aware inspection instant, and authenticated actual service readbacks. A structurally correct test fixture does not establish authentic identity.

`verify_private_network` requires nondefault IPv4 RFC1918 VPC with DNS support + DNS hostnames; two available IPv4-only subnets in different owner-region AZs without public IP mapping; **explicit task route tables without IGW, NAT, transit, peering, arbitrary or IPv6 external routes**; private DNS enabled and pinned interface endpoints `ecr.api`, `ecr.dkr` and `logs` spanning both task subnets; **S3 gateway route + shared prefix list on each subnet route table** for ECR image layers; no task inbound ports; task outbound limited to TCP443 to endpoint SG plus the S3 prefix list; and endpoint inbound restricted to TCP443 from task SG. This is intentionally stricter than some production architectures, and may reject safe alternatives until reviewed. **It is not evidence a real network has been configured or a task could reach arbitrary internet services.**

`verify_signed_owner_image` cryptographically validates the raw **Ed25519 signed message bytes** against the independently pinned owner public-key fingerprint, exact account/region/source commit/image digest/repository and B4c2 source workflow reference, with bounded timestamps. It independently reads exact ECR repository `IMMUTABLE` tag policy, account- and Region-qualified repository URI, digest-selected image and a **completed ECR scan** with zero HIGH/CRITICAL findings. A scan is point-in-time and may not provide comprehensive vulnerability coverage. Owner source metadata and signature alone **do not** verify OCI/ECR AWS Signer signatures, reproducible image builds, actual runtime policies, or image licensing. These remain explicitly `false` in the returned evidence. ECR enhanced scanning differences require a future separately reviewed implementation; unknown status fails closed.

Both APIs return `release_authorized: false`, `actual_cloud_deployment: false`; the combined API additionally returns `owner_activation_still_required: true`. They expose no `RunTask`, `CreateService`, `CreateVpc`, billable model inference, owner-secret fetch, or Google publishing action.

## Cloud-hosted tests and boundary

`.github/workflows/flowminute-b4c3-private-network-image-readonly.yml` uses **read-only contents permissions**, checkout without persisted credentials, Python 3.11, and the cryptography verifier package. All EC2/ECR calls go to invented in-memory clients with only `describe_*` methods and only synthetic AWS IDs. CI adversarially rejects:

- public subnets, public IPv4, IPv6, duplicate AZs, default VPC, disabled VPC DNS;
- Internet gateways/NAT/transit/peering routes, missing exact S3 gateway prefix-list route, blackholes;
- incomplete ECR/CloudWatch interface endpoints, wrong DNS/SG/subnet coverage, broad ingress/egress;
- forged/replayed/mismatched/expired or owner-key-unpinned signatures;
- mutable ECR repository or cross-account ECR image, wrong source digest, incomplete scan or HIGH/CRITICAL findings;
- all attempts to imply verified owner billing, deployed Fargate task, real publishing or YouTube upload.

CI never takes the owner OAuth secret from the private repository and makes **zero AWS runtime/deployment calls**. The compiler/test runner is GitHub-hosted, not the owner's laptop. Tests cannot substitute for a real third-party signed image attestation, AWS live IAM inspection, cost approval, or actual operator-initiated deployment.
