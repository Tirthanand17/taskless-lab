# ADR-0018 — B3d4c1: executed educational demonstrations, original visuals & unapproved thumbnail proofs

**Date:** 2026-11-04; **Branch 2:** cloud autopilot; **status:** read-only GitHub technical preflight, NOT real original daily editorial production or publishable YouTube media.

## Research and motivating gap

The merged B3d4b technical cloud pipeline can genuinely produce three full-resolution Kokoro-narrated MP4s with original placeholder scene cards, subtitles and independently measured FFmpeg audio/video quality. The script is externally signed in a disposable test fixture, not fact-reviewed or generated by a connected provider. But the earlier generic storyboard cards only showed textual visual instructions. A high-quality educational video should **visibly execute and explain something**, not merely repeat templated text.

Current first-party YouTube policy reviewed on 2026-11-04:
- [YouTube channel monetization policies](https://support.google.com/youtube/answer/1311392?hl=en): channel must offer original, authentic substance; repeated mass-produced generic slide formats, interchangeable plotlines, minimally varied templates and low-value commentary may violate inauthentic content rules. Passing a template detector is not proof of compliance. Genuine editorial creativity and viewer benefit require human assessment.
- [Disclosing use of GenAI content](https://support.google.com/youtube/answer/14328491?hl=en): realistic meaningful alterations should be disclosed; script/thumbnail ideation or clearly nonrealistic illustrative animation generally differs. **The platform's eventual disclosure decision must be reviewed for the exact resulting audio/video.**
- [Pillow ImageDraw reference](https://pillow.readthedocs.io/en/stable/reference/ImageDraw.html): draw original text, boxes, tables and diagrams at exact sizes without borrowing stock imagery.
- [Existing signed cloud voice ADR](0017-b3d4b-signed-script-tts-and-av-qa.md) and B3d4b actual GitHub-hosted test results: Kokoro output and encoded caption QA are already implemented and should be reused.

**Decision:** Address the measurable content-specific value gap without falsely claiming we have activated a private Gemini account, authentic human reviewer registry, copyright rights, YouTube publishing or original externally supported breaking-news facts.

## Implementation

1. Add three **allowlisted, reproducible, standard-library computed tutorial contracts** using the existing four synthetic CSV rows. Only explicit author-selected recipe IDs are accepted; never execute arbitrary model-authored code. Fixed results are independently recomputed on invocation:
   - preserve_text_identifiers: Python CSV reader preserves the original five-character '00127', whereas int conversion becomes 127, removing two leading zero characters; not a universal identifier rule.
   - validate_iso_dates: date.fromisoformat accepts three rows matching the example's YYYY-MM-DD business rule; the fourth raw '11/04/26' is flagged and preserved without guessing its date interpretation.
   - review_duplicate_keys: original rows 1 and 3 have the same sample key but different joining dates; record the conflict, keep both records and produce a review list instead of automatically deleting records.
2. Restrict recipe-to-script match to exact expected topic phrase in the **signed** title, a topic-specific authored example walkthrough, and original narration. The match is a **LEXICAL guardrail only**, not semantic assurance that each visual is synchronized to each sentence or that any claim is factually true. Unsupported topics and wrong scripts fail closed.
3. Produce a deterministic SHA256-bound evidence packet containing synthetic input CSV hash, algorithm identifier, actual computed outcome and exact visual step texts; no source article, real customer data, original model secret or raw external content. The video producer re-runs both B3d1 signed-source continuity and this computation, refusing changed scripts, forged panels or privileged flags.
4. Replace previously generic visual beat text cards with three subject-specific families of ORIGINAL 1080×1920 or 1920×1080 tutorial graphics depicting the actual computed before/after outputs and source row values. The existing B3d4b Kokoro speech, PCM-timed SRT, original scene transition tone/moving progress overlay and FFmpeg H264/AAC remain in use. Explicitly label computed frames as synthetic test data with *no factual or rights approval*.
5. Render one custom 1280×720 **UNREVIEWED_THUMBNAIL_TEST.png** per example, with actual educational theme and no false numeric marketing claim. The thumbnail stays inside an ephemeral CI temp directory; it is not a YouTube upload or licensed asset assertion.
6. In a standard unprivileged GitHub-hosted pull_request workflow, run extensive fake-source/signature and computed-outcome negative tests, then download only exact previously approved public SHA256 Kokoro weights, execute the actual Python tutorials, synthesize three full narrated examples, and inspect all original PNG frames and thumbnails plus actual encoded FFmpeg audio/video/caption quality. Require all distinct outputs and clean deletion of unapproved WAV/SRT/PNG/MP4/model weights after the run.

## Trust and editorial boundaries

- A computed synthetic CSV example proves only that THIS CODE produced THIS RESULT from THESE MADE-UP ROWS. It cannot substantiate a claim about current AI products, business statistics, news, legislation, historical events, sources, creative novelty or real audience preferences.
- The model-proposed topic's lexical text match does not prove that the scene depicts the meaning of the exact spoken sentence. A true independent human must review and correct scene/narration synchrony, full watch/listen and the final thumbnail.
- **No actual externally connected generative model** has provided scripts for this branch; the three test scripts remain inherited fixtures from earlier B3c. Models, facts and rights are not human approved. Synthetic Kokoro voice licensing and rights require separate due diligence before public use.
- YouTube inauthentic/repetitive-content policy cannot be reduced to deterministic uniqueness hashes or the mere fact that three sample recipes differ.
- All output media exists only in unprivileged GitHub-hosted ephemeral CI; the specific digest, test model or a quality pass is not a publishing authorization.
- No private source body, OAuth credentials, personal customer files, local machine, persistent media, budget account, upload, schedule or monetization action is created.

## Acceptance and what remains

**B3d4c2:** owner-approved secure live generative provider account, consented data use + budget cap; genuine independent source evaluation with real author/reviewer enrollment; novel evidence-grounded scripts that each provide a meaningful viewer outcome, **not repeated demos**; truly bespoke programmatic or authored visual examples and substantive animations across broader topics; voice licensing and originality proof, actual human playback/editorial/rights reviews and signed final MP4+thumbnail+metadata records.

**B4:** separately authorized private durable storage, OAuth credential custody, independently signed approvals on immutable externally pinned final assets, fenced exactly-once remote YouTube uploads as private, remote SRT/thumbnail/processing verification and future scheduled releases.

**B5:** seven consecutive days of 21 genuine, individually reviewed, unique published videos at 11:00, 16:00 and 20:30 Asia/Kolkata with the user's laptop off.

Branch 1 assisted YouTube release workflow is independent, unchanged and not bypassed.
