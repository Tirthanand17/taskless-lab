# ADR-0026 — B3d4c2c2 signed final editorial receipt coverage, NEVER a release grant

**Date:** 2026-11-04 IST. **Scope:** Branch 2 fully unattended YouTube goal, GitHub-only mock role/evidence engineering. **Status:** prototype review/signature boundary, no real human or publisher activation.

## Sources and motivation

- YouTube [inauthentic content and monetization](https://support.google.com/youtube/answer/1311392): original substantive educational work and creative variation matter. Different MP4 SHA values, titles or visual colors across a template alone cannot demonstrate materially original videos; AI-generated low-variation mass production may violate monetization rules.
- YouTube [disclosing AI-generated content](https://support.google.com/youtube/answer/14328491): realistic AI-altered/synthetic depictions have disclosure criteria; not all script-generation assistance requires disclosure. A real final-media owner/reviewer must choose the correct declaration. This mock gate cannot automatically declare YES/NO for production.
- YouTube [copyright](https://support.google.com/youtube/answer/2797466): use of protected audiovisual works, music and voice recordings requires appropriate rights/legal exceptions. A URI, SHA or generated model name does not establish a license. Copyright claims/strikes remain possible even with purported license documents.
- YouTube [videos API](https://developers.google.com/youtube/data/reference/rest/v3/videos): status.containsSyntheticMedia, status.privacyStatus, status.publishAt are publisher-side decisions. This module imports no YouTube API and never sets upload status.
- Existing project PR #28 introduced exact MP4/SRT/WAV/thumbnail/all scenes byte-lineage over three authentic FFmpeg/Kokoro cloud test files, but no owner/claim/rights/originality approval.

## Decision and trust boundary

Implement autopilot/mock_final_editorial_review.py and adversarial tests on GitHub only. Rebuild all actual final files from the previous evidence gate, including source-bound original signed script/scene/source observations and exact byte SHA/length. Independently **re-run** B3d3b cryptographic review of source surface and at least ONE atomic claim with a cited synthetic source excerpt. Reject vacuous zero-claim packets rather than silently claiming a fact-bearing real script is approved. This currently blocks 2/3 older synthetic test topics, which are NOT remediated by pretending they were fact checked.

Bind proposed title, description, thumbnail claims, citation-root SHA, voice+image+music licensing-root SHA and prior-channel-release originality-root SHA to the exact final file inventory. The metadata field actual_synthetic_disclosure_decision must remain PENDING_OWNER_REVIEW. The roots are *requirements*, not proof that actual source/license/release-index records exist. All sources, source body excerpts, signatures and release history used by CI are synthetic; no account or URL reader is configured.

Require a detached Ed25519 receipt for each of SEVEN distinct hypothetical final-review roles:

1. independent_fact_sufficiency — original B3d3b atomic source claim docket/claim count and proposed real citation index;
2. final_visual_caption_title — complete final MP4, scene hashes, SRT, thumbnail, title and description;
3. originality_against_channel — exact script and computed teaching demonstration plus prior approved channel release index head;
4. voice_music_image_rights — signed asset/voice/WAV/thumb inventory and hypothetical license evidence index;
5. altered_synthetic_disclosure — review of exact final MP4/voice and a mock DECLARE YES/NO decision;
6. human_full_watch_listen — final exact MP4/SRT/WAV and a **self-declared** watch duration at least equal to the video's duration;
7. channel_owner_release_intent — a separate hypothetical channel owner signer tied to the actual video, metadata, claims, asset rights and previous approved releases.

Each role has one separately supplied, active, role-specific Ed25519 public key, different reviewer ID, key ID and public bytes, bounded 24-hour freshness / 36-hour validity, source and asset digest, distinct receipt ID, domain-separated signature, and explicit reviewer notes. Exclude content creator/publisher/model agent identifiers. Reject invalid signatures, revoked/expired keys, changed MP4/thumb/scene/SRT, altered public text, wrong source claim, forged role, reused key, replay, missing duty and tampered external docket digest. Incomplete or signed rejected cases block a structural pass.

**Critical:** an attacker could generate seven mock signers and self-attest every fact/right/experience if allowed to control the public-key registry and external digest. All CI signers are generated by software. A purported full-watch duration can be written without actually watching, and a mock disclosure choice can be arbitrary. This test proves ONLY signature syntax, mutual separation and exact artifact lineage. Even when all seven MOCK_ACCEPT records are cryptographically valid, output remains real_source_fact_accuracy_and_claim_completeness_verified=false, human_full_watch=false, real_licensing=false, originality=false, actual_disclosure=false, owner_permission=false, private_immutable_review_ledger=false, youtube_upload_enabled=false and release_authorized=false. NEVER wire these mock results into a future publisher.

Real human identity, owner authority, evidence/copyright/license validity, accurate atomic-claim completeness, previous-channel originality comparison, approved metadata, actual watch/listen and external private trust store must be verified by a distinct owner-approved system before real release. In production it must verify exact final video/thumbnail/captions without remixing after signing.
