# ADR-0075 — B4e0b live GitHub voice bootstrap: never call apt

**2026-11-06 IST | Branch 2 | GitHub hosted runner only | fix after trusted real main-run failure**

The previous PR #84 correctly passed four isolated pull-request GitHub checks and was merged, but the actual real **trusted main** execution [42242580566](https://github.com/Tirthanand17/taskless-lab/actions/runs/42242580566) failed before generating speech/media. All standard Python wheels installed successfully in under ~10 seconds, including `kokoro-onnx==0.6.1`, the `espeakng-loader-0.2.4` platform wheel containing a Linux binary library **and** phoneme data, Pillow, numpy, soundfile, FFmpeg wheel, onnxruntime and phonemizer. Then the fallback `sudo timeout 110 apt-get install espeak-ng` hung exactly until **exit 124**. This is a structural duplicate of the repo's earlier apt mirror failure (which previously motivated wheel-based FFmpeg).

**Fix:** Delete the system `apt-get` fallback entirely. Specify the exact `espeakng-loader==0.2.4` release from wheel in the already installed dependencies, then verify its `get_library_path()` file and `get_data_path()` directory exist. Physically load that exact bundled library with `ctypes.CDLL` before passing Kokoro into TTS. The public Kokoro 0.6.x tokenizer itself sets its eSpeak library and data paths directly using these loader APIs, so a system-wide binary package is redundant. No `sudo`, no apt update, no external eSpeak installer, no paid TTS fallback.

**Guards:** Four dedicated standard-Python tests check the actual GitHub workflow source has no `sudo` or apt install, pins the bundled wheel, physically checks library/data references, retains exactly the existing read-only GitHub permissions and zero paid/release flags, and still destroys the real WAV/MP4/image/model output even if media fails. Keep 26-minute overall cap, fixed media stage limits and exactly two sanitized research receipt outputs. No public use of unreviewed Kokoro voice rights, copyrighted article text, final news claims or YouTube uploads.

**Acceptance:** Four exact-head PR CI checks pass, then **new trusted main** daily run must move PAST dependency and model-asset setup to the real B4e0 CPU voice/six original image frame physical encoder. If it produces fewer than three actually decoded previews, fail rather than misreporting media as completed. The original B4e0 run yielded **zero** physical preview files. This is not completed until the new run reports 3 actual previews and 0 full daily releases.
