# ADR-0031 — B3d4c2d2 version-pinned reviewer binding after S3 escrow (SYNTHETIC ONLY)

**Date:** 2026-11-04 IST. **Branch:** 2 (unattended 2 Shorts + 1 long daily). **Decision:** re-fetch every stored original media asset by its exact S3 object VersionId, verify the original source and all media hashes, and cryptographically bind **seven strictly separate reviewer MOCK receipts** to the complete immutable-version context. This is a software correctness milestone, **NOT** a real human/owner identity enrollment, content license, fact check, permanent private cloud deployment or YouTube publishing approval.

## Context and researched official semantics

PR #31 physically encoded/independently decoded three different source-linked Kokoro H264/AAC narrated videos on a disposable GitHub-hosted runner (61.79 / 219.12 / 60.02 sec, 70 SRT cues, 160 distinct animated vector PNGs, 213 original scene/voice/video/thumb/claim-bound media outputs). Those real files were DELETED at the end of the job. PR #32 indexed 210 exact spoken/visible/original thumbnail/title-description textual surfaces and six live NASA/NIST/USGS sources. PR #33 built a real boto3 API adapter and successfully staged/read back **213 invented NONPLAYABLE fake media assets + 3 unapproved manifests** on a separate local Moto HTTP process. No actual persistent private video bytes exist yet, no owner account or signers are enrolled, and no real reviewer has inspected the complete media.

Amazon documents that S3 [GetObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html) with a specific VersionId requires GetObjectVersion permission and does not silently select the latest key. [HeadObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html) can return exact version ID, SHA checksum metadata, KMS key and ObjectLock metadata when appropriate permissions exist. [Object Lock management](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html) requires independent GetObjectRetention permissions to prove lock expiry; a GET without sufficient permissions may still succeed without retention fields. The verifier fails closed when retention metadata is missing, when a version is expired or replaced, or when the returned object bytes, metadata, checksum, KMS key or source docket differ. Object Lock on an emulator is not production legal immutability and SHA is not a real independent human sign-off.

The Python cryptography library supports detached Ed25519 verification with domain-separated signatures. Its official [Ed25519 documentation](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/) specifies that wrong signatures raise InvalidSignature. All test private keys are randomly generated only in memory on a GitHub-hosted runner and destroyed at the end of the test.

## New workflow

1. **Root the immutable original source.** Independently rebuild exactly one of the approved-format repository-authored NASA/NIST/USGS technical *drafts* and its exact unapproved claim/visual/metadata docket; require matching source SHA root and 43 / 127 / 43 original inventoried items from the escrow plan. Never trust a model-generated source link or self-reported media SHA.
2. **Read the exact S3 final manifest version.** Accept a proposed bucket/region/customer KMS key and a separate externally passed escrow receipt (not genuine owner proof). Use its exact pinned final manifest VersionId, full SHA and count to HEAD+GET that version. Parse strict canonical JSON without duplicate keys; require all unapproved flags FALSE, exact original episode, original producer media inventory, source docket SHA, correct count and ordered manifest asset entries. No "latest" GET and no fallback to an alias.
3. **Read every original object again.** For each manifest-listed file perform a second separate HEAD+GET specifying its exact VersionId; bound response body length, SHA256 of all returned bytes, check head+get VersionIds, checksum, SSE-KMS key ARN, COMPLIANCE retention still valid at actual read time, episode/source metadata and no extra/duplicate/swap. This is read-only and does not alter the retained object. Build a new canonical hash of the entire list of original key + VersionId + SHA + byte size, including the MP4, WAV, SRT and thumbnail version IDs as named critical assets.
4. **Construct one version-bound review context** with the real fetched manifest key/version/hash, entire S3 asset versions hash, 210-surface claim binding, 14 curated research claims, exact episode/date/slot, full runtime claim, KMS config and original physical producer SHA. All real fact/rights/full-watch/identity/YouTube/release flags hard FALSE, even if a robot hashes every byte correctly.
5. **Seven independent role-specific synthetic Ed25519 signatures.** The roles reuse PR #29: independent source fact sufficiency, final visual/caption/title, prior-channel originality, voice/music/image rights, altered/synthetic disclosure, full-watch/listen, and channel-owner release intent. Each fake public key is supplied by a separately constructed synthetic registry and matches one exact permitted role and identity; all seven identities, public keys, key IDs and receipt IDs must be unique, not creator/model/publisher IDs. Each claim signs a distinct domain-separated hash of the exact complete version-bound context, role, decision, 24-hour freshness, bounded expiry, notes, plus mock full-watch duration and disclosure choice. Reject swapped media/versions, source docket, unsigned/forged/replayed receipt, wrong role, repeated key, invalid timestamp, missing full watch duration, undecided disclosure. A signed MOCK_REJECT/UNRESOLVED blocks even synthetic completion. No mock receipt ever sets real approval or release true.
6. **Explicit independent enrollment gap.** The demo registry is generated in-memory in tests. Even a separately supplied registry digest can be forged by a caller who controls both registry and expected digest; it does not authenticate a human or account. The code deliberately only reports SYNTHETIC verification, with owner_identity_authenticated=false, real rightsholder/claim/full-watch/AI decision=false, immutable private approval ledger=false, youtube_upload_enabled=false, release_authorized=false. Production must use a separate real owner-controlled IAM identity, publicly/verifiably enrolled real human reviewer keys or independent proof-of-control, tamper-evident external registry and revocation state, actual source context and content review, and final approved video bytes; none exist yet.
7. **Real S3 API compatibility test, NO AWS.** GitHub hosts a separate ephemeral localhost Moto S3 HTTP server. Actual boto3 with dummy credentials and retries disabled writes the 213 invented NONPLAYABLE fixture files plus 3 unapproved manifests, then performs 213 new version-ID-specific HEAD+GET SHA/content/KMS/retention checks, builds three distinct review context roots, and verifies 21 unique synthetically signed role receipts (seven per video). B3d4c2d2 test fails on missing content/rights, changed exact media/HTML claims, fake authority, swapped versions or unreviewed disclosure. All synthetic media and private fake keys are destroyed after job; no paid cloud account, laptop, real provider, Amazon or YouTube call.
8. **GitHub CI and merge discipline.** New read-only .github/workflows/flowminute-b3d4c2d2-version-pinned-reviews.yml runs no-network adversarial unit tests plus local emulator HTTP. Existing Content Quality Gate, public scout and other applicable regressions must be green before merge. ## Threat model / explicit limitations

S3 object VersionId, COMPLIANCE retention, original MP4 SHA, independent role key cryptography and even seven synthetic mock signoffs **cannot grant actual rights, human truth or ownership**. A signed role may lie, reviewer might be AI, owner account may be someone else, an external catalog may show duplication, and videos may use a voice/model that violates terms. The new code checks that signatures are mathematically valid against a caller-provided synthetic registry and that stored bytes match the original temporary fixture; **it cannot establish that a real human independently watched or fact-checked them**.

A S3 emulator cannot prove real AWS KMS encryption, owner account/billing, IAM least privilege or object lock durability, nor separate immutable ledger commitment. The repository is public and must not contain actual API credentials, actual uploaded media bytes, production keys or private source bodies. No actual YouTube OAuth/upload/schedule or owner-approved third-party cloud provisioner has been built or used. The watched seconds in test are purely made-up synthetic assertions.
